C. 구현 내용

1) 사용자 흐름 / UI
- AddComparedProductToClosetSheet는 선택 사이즈 API 실측을 첫 frame부터
  표시하고 수정/추가 가능한 Closet-local draft를 사용한다.
- ClosetItemDetailView의 linked item 편집도 동일한 measurement editor를
  사용한다.
- 전체 판매 사이즈는 유지·표시하고, 실측이 없는 사이즈만 등록 대상으로
  비활성화한다.
- 기존 FitMatchTaxonomyProvider, bundled taxonomy,
  FitMatchMeasurementStandard 정의를 재사용한다.

2) Snapshot / provenance
- FitMatchClosetMeasurementSnapshot은 ProductSize chart뿐 아니라 현재
  UserFit의 owned snapshot에서도 생성할 수 있다.
- 같은 exact size의 category-only 또는 measurement-only 편집은 기존
  USER_MANUAL row를 보존한다.
- 실제 size 변경은 새 exact ProductSize chart에서 시작한다.
- 수정한 항목만 USER_MANUAL이며 untouched API row는 RETAILER_SNAPSHOT이다.
- 신규 FitMatch measurement는 retailer source identity를 위조하지 않고
  raw/source code를 null로 유지한다.
- 소수 정밀도(예: 55.25)를 표시용 한 자리 반올림으로 훼손하지 않는다.

3) Transport / hydration / sync
- linked payload의 measurements를 product linkage 때문에 생략하지 않는다.
- DTO → UserFit → measurementRecords에서 value_source와 source identity를
  복원한다.
- 서버에서 source가 없었던 USER_MANUAL 추가값은 다음 sync에서도 source
  null을 유지한다.
- coordinator가 editor snapshot을 ProductSize에서 다시 생성하지 않고
  그대로 upsert/update 요청에 전달한다.
- unrated satisfaction 0은 서버에 임의 3으로 저장하지 않고 null/omitted로
  round-trip한다.

4) Isolation / 기존 동작
- 사용자 Closet 편집은 shared Product, ProductSize,
  product_size_measurements 또는 다른 사용자 Closet을 변경하지 않는다.
- 직접 입력 Closet은 기존 generic upsert/update route를 유지한다.
- parser, 원본 상품/category metadata, 전체 판매 사이즈, 자동분류 자산,
  diagnostics, 기존 UI style은 유지했다.
