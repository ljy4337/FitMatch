## 1. Execution meaning

A row is one behaviorally distinct user scenario. A row may contain a fixture
matrix only when every subfixture has the same user intent, policy gate,
recoverability, terminal state, and user-visible outcome. Each listed subfixture
must nevertheless be constructed and executed; one representative cannot stand
in for the others.

A scenario is EXECUTED only when its distinguishing state is present in the
constructed production DTO/model and the required production symbols are
reached. A source-string assertion or a label-only fixture is not execution.
Private SwiftUI-only behavior with no safe test injection seam is NOT_EXECUTED,
not PASS. The harness may fake auth/network ordering only; it may not reproduce
classification, reference policy, manual-cross policy, size eligibility, or the
scorer.

Provenance is exactly one of LIVE_RETAILER, PRODUCTION_PUBLIC_SELECT,
REPOSITORY_REAL_SNAPSHOT, SYNTHETIC_ADVERSARIAL, or POLICY_STATE.

## 2. Equivalence rules

E01. Required-field validation may share one scenario only when each field is
actually cleared in a separate subfixture and each reaches production validation.
E02. A provider parser path never collapses into another provider path.
E03. A server terminal gate collapses downstream axes only after proving that no
downstream engine/result/history symbol is reached.
E04. Manual-cross pairs may share a scenario by action mode only when all three
protected pairs and both directions are separately instantiated.
E05. Measurement failures may share a scenario only when every named semantic
failure is separately represented and the production reason mapping is observed.
E06. Availability failures are distinct from Recovery/classification success.
E07. A current-session Result and a cold reconstructed History are never equivalent.
E08. Local legacy History and server-completed vNext History are never equivalent.
E09. Static-only reverse-scan evidence can explain a failure or missing seam but
cannot turn a row into PASS.
