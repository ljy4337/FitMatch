Root cause (static and runtime-correlated):

* ShoppingProductViewModel.makeProduct marks a runtime classification with
  authority_status == USER_EXPLICIT as `.userExplicit`.
* ShoppingProductViewModel.completeVNextRecommendation calls the real engine,
  successfully completes the server comparison, then asks
  RecommendationService.makeCompletedVNextHistory to create the local model.
* RecommendationService.makeCompletedVNextHistory has a hard guard requiring
  `product.classificationAuthorityProvenance == .serverConfirmed`; it rejects
  `.userExplicit` even though that provenance is the reviewed, server-backed
  authority for the current comparison.

Evidence locations:

* FitMatch/ViewModels/ShoppingProductViewModel.swift:831
* FitMatch/ViewModels/ShoppingProductViewModel.swift:1050
* FitMatch/Services/RecommendationService.swift:70

  부족해 추천할 수 없습니다.” after the exact permitted chain already reached
  `complete_comparison`.
* J13: UNEXPECTED_STALL/WRONG_RESULT.  The app says there is no compatible
