# 점수 정책 결정 자료

## 최신 결정 — 2026-10-02

사용자가 “니가 알아서 … 알고리즘을 만들어서 적용”하라고 결정권을 위임했다. 에이전트는 1차 출시에서 현재 검증한 점수·반올림·동점 규칙을 유지하기로 결정했다. `Docs/FitMatchMeasurementPolicy.md §4.4`에 제품 기준으로 명문화했고 테스트정책3항목을 RESOLVED로 변경했다. 산술코드·기존숫자정답·UI·DB는 변경하지 않는다. 아래는 결정 전 조사 기록이며 UNRESOLVED/승인대기 표현은 이 결정으로 대체된다. 임상적/통계적 최적 정확도가 입증됐다는 뜻은 아니다.


**결론:** 기본 `1cm 차이당 5점 감점`의 과거 문서는 있다. 그러나 현재 서버 승인 비교 경로의 공식 전체, 두 단계 반올림, 완전 동점 순서를 독립적으로 승인한 제품 기준은 이번 제한된 문서 조사에서 확인하지 못했다. 세 항목의 `UNRESOLVED`를 유지한다. 이 자료는 정책 승인이나 제품 변경이 아니다.

## 확인한 근거

- 현행 정책은 서버 승인 실측만 사용하고 상의 가중치를 가슴 2, 어깨 1.5, 총장 1, 소매 1로 정한다. 공식·반올림·동점 순서는 명시하지 않는다. `Docs/FitMatchMeasurementPolicy.md:64–77`.
- 과거 비교표는 5점/cm, 항목별 0–100 제한, 가중 평균을 명시한다. 다만 같은 문서의 최소 2항목·상의 가중치 1.4/1.2/1/0.8은 현행 정책과 다르며, 반올림·완전 동점 규칙은 없다. `Docs/무신사_유니클로_카테고리별_사이즈저장_비교표.md:228–258`.
- 과거 흐름의 항목별 `rounded()`는 제목부터 “현재 코드 공식”이고, 추천 동점 설명은 평균 차이까지만 있다. 구현 설명을 독립 제품 승인으로 승격할 수 없다. `Docs/flows/12_FitConfidenceFlow.md:3–12`, `Docs/flows/11_RecommendationFlow.md:6–21`.
- 8월 handoff도 공식·순위를 변경하지 않았다는 보존 기록이다. 현재 정책의 명시적 승인 기록은 아니다. `Docs/CodexSessionHandoff.md:2444–2448,2644–2649`. 기존 감사 결론과 일치한다. `ExpectationAudit.md:14–33`.

## 현행 규칙을 적용한 산술 사실

아래는 기존 특성화 자료의 규칙을 직접 계산한 예다. 숫자가 계산과 일치한다는 사실과 그 규칙이 제품 정답이라는 승인은 별개다. 근거: `ExpectationAudit.md:21`, `NumericBoundaries.md:7–17`.

| 항목 | 숫자로 보는 현재 결과 |
|---|---|
| 공식 | 차이 0/2/20/21cm → 항목 점수 100/90/0/0. 서버가 승인한 항목과 가중치만 평균에 사용한다. |
| 반올림 | 항목 원점수 97.5·92.5, 가중치 2·1.5 → 각각 98·93 → `(98×2+93×1.5)/3.5=95.857…` → 96. 마지막에만 반올림하면 95가 된다. 양수 `.5`는 올린다. |
| 동점 | 두 사이즈가 모두 99점이면 가중 절대차 평균 0.214…cm가 0.286…cm보다 앞선다. 평균까지 같으면 정확한 size UUID 문자열 오름차순이다. UUID 순서는 더 잘 맞거나 더 작은 사이즈라는 의미가 없다. |

## 권장안과 필요한 결정

**권장안:** 기존 공식·두 단계 반올림·동점 순서를 그대로 유지하고 현재 비교 경로의 제품 기준으로 명시한다. 이번 준비 범위에서 화면 점수와 순위를 바꾸지 않으면서 앞으로 구현과 독립된 정답표를 만들 수 있다. 과거 snapshot도 그대로 보존한다.

**고려할 점:** 두 단계 반올림은 마지막만 반올림할 때보다 예시에서 1점 높다. UUID는 완전 동점의 순서를 일정하게 만들지만 착용감 우선순위를 뜻하지 않는다. 이 동작이 원하는 제품 의미인지 결정해야 한다.

사용자에게 필요한 질문: **“위의 현행 계산·반올림·동점 규칙을 그대로 유지하고 공식 제품 기준으로 명시할까요? (권장: 현행 유지 공식화 / 대안: 결정 보류)”**

승인 전에는 제품·정책·동결 기대값·해시를 바꾸지 않는다. 보류하면 회귀 특성화 증거를 유지하고 세 정책 기준은 미확정으로 남긴다. 전체 테스트나 출시 승인을 이번 준비의 추가 완료 조건으로 만들지 않는다.
