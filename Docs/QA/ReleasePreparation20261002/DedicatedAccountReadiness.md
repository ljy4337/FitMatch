# 제공된 테스트 계정의 사용 가능 여부

## 최신 — 15% 한도 재개 / 초기화 미적용

- 사용자는 개발 DB의 지정 계정 데이터를 초기화해 테스트하는 것을 승인했다. 아래의 B 제외 결정은 이 승인으로 대체된다.
- A는 활성 옷/비교가 0/0, B는 6/9다. B의 전체 행은 삭제된 행까지 옷 67/비교 38이며, 이번 초기화 계획은 **활성 6/9행만 기존 삭제 표시 방식으로 처리**하는 것이다. 물리 삭제가 아니다.
- 실제 배포된 `soft_delete_closet_item`과 `hide_comparison_history`, 관련 trigger/FK를 확인했다. 계정·원본 실측·완료 결과 snapshot·기존 tombstone·다른 사용자 행을 보존하는 단일 transaction을 요청했으나 **자동 승인 검토가 관리자 SQL 변경을 거부했다**. 적용 0건. 거부 후 READ ONLY로 A 0/0, B 6/9가 그대로임을 재확인했다.
- **이메일 계정 추가는 필수가 아니다.** 실제 Swift/DB 하네스는 정상 Apple 로그인 세션도 허용한다. `release_qa_session.py`의 비밀번호 로그인 기능만 Apple-only B의 세션을 만들 수 없다. 앞선 “빈 이메일 계정 1개가 반드시 필요” 설명은 이 내용으로 정정한다.
- 정상 로그인 access/refresh session은 현재 연결되어 있지 않다. 초기화가 승인·적용되어도 사용자 권한의 실제 DB 검사에는 별도 정상 인증이 필요하다. UID·관리자 대시보드 로그인·관리자 SQL은 이를 대체하지 않는다.

실행 증거와 차단 사유: [Resume15Report.md](Resume15Report.md). 이메일·UUID·인증값은 기록하지 않는다.
