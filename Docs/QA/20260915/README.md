## 발견한 문제

### 1. 무신사 슬랙스의 서버 등록 차단 조건이 남아 있음 — 우선 해결

- 대표 링크: https://musinsa.onelink.me/PvkC/tlrprnvi → 상품 `5746364`.
- 이번 전체 파서 실행에서 상품과 실측을 받아왔습니다.
- 현재 서버에는 슬랙스의 `lower_length_code`가 없으면 거부하는 기존 조건이 남아 있고, `바지 > 슈트 팬츠/슬랙스`의 정확한 그룹 경로 매핑도 없습니다.
- 미매핑 그룹 선택 화면까지 가기 전에 상품 등록에서 막히는 원인이 남아 있다는 뜻입니다. 실제 로그인 요청의 재현은 아직 BLOCKED이며, 이번에는 현재 서버 정의를 읽어 확인했습니다.
- 준비된 SQL 파일은 서버에 적용하지 않았습니다.

### 2. 공식 사이즈표의 팔둘레가 파서 결과에서 누락 — 확인된 실측 누락

- 상품: [무신사 6372903](https://www.musinsa.com/products/6372903).
- [공식 사이즈표 이미지](https://fit6.cre.ma/mixxo.cafe24.com/fit/products/12726/combined_fit_product.jpg?width=780)를 눈으로 확인한 뒤 이번 파서 결과와 대조했습니다.
- 어깨·가슴둘레·소매·총장: 3개 사이즈의 12개 값이 원본과 일치합니다.
- 팔둘레: S=28, M=29.5, L=30.5cm가 원본에 있지만 반환된 실측 목록에는 없습니다.
- 가슴둘레 84/88/94cm는 둘레로 유지됐습니다. 이 한 상품의 확인을 다른 184개 상품의 전체 실측 정확성 검증으로 확대하지 않습니다.

### 3. 일부 상품의 이미지 분석이 오래 걸림 — 아이폰에서 지연 확인 필요

- 무신사 `6372903`: 약 157초, `6372893`: 약 179초.
- 185개 전체의 상품당 중앙값은 약 1.81초입니다.
- 두 상품은 이미지에서 글자를 읽는 과정이 길었습니다. 시뮬레이터에서는 CPU로 처리됐고 일부 다른 검사도 함께 실행했으므로, 이 시간을 아이폰의 실제 대기 시간으로 단정하지 않습니다.
- 해당 두 상품의 로딩·취소·다시 시도를 아이폰 14 Pro에서 우선 확인해야 합니다.

### 4. 기존 자동 테스트를 현재 정책에 맞게 정비해야 함 — 전체 통과 아님

- 완료된 묶음: **658 PASS / 82 FAIL / 42 NOT RUN**. Xcode의 `Skipped`는 여기서 NOT RUN으로 표시했습니다.
- 별도 `FitMatchHeadlessUserJourneyTests` 묶음은 가짜 서버가 현재 필수인 상품 전송을 무조건 거절한 뒤, 도달할 수 없는 응답을 계속 기다려 중단했습니다. 첫 실행의 부분 결과를 위 수치에 더하지 않았습니다.
- 확인된 오래된 기대값: 폐기된 기준 옷 자동 지정, 둘레를 절반으로 바꾸는 이전 측정 정책, 예전 서버 요청 순서, 변경된 화면 문구.

- 예전 테스트의 기대에 맞추기 위해 앱의 정책을 바꾸지 않았습니다.
