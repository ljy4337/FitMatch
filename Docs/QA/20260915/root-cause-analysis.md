## 비교 숫자 실패 추가 분석

`MeasurementPolicyConsolidationTests`의 두 실패는 동일 fixture를 사용한다. 상품은 허리 **단면 80**, 내 옷은 허리 **둘레 78**로 명시되어 있다.

- `canonicalNewMerchantSupportsVerifiedSameSourceRawComparisonWithoutEngineChanges`: 기대 차이 2와 점수 92는 서로 다른 측정 기준을 그대로 빼는 이전 기대다. 현재 엔진은 비교 시 78/2=39로 환산하므로 허리 차이는 41이다. 이번 실행 점수는 44였다. 원본 데이터 문제가 아니라 fixture/기대값 정비 대상이다.
- `unknownSourceDoesNotGainSameSourceRawCompatibility`: 출처명이 없어도 두 record가 mapped이고 명시된 허리 단면/둘레 조합이면 현재 엔진은 verified_conversion을 허용한다. 이 테스트는 같은 출처 원본 비교의 거부와 검증 환산의 허용을 혼동한다. 실제로 의미가 불명확한 record가 환산되는지는 별도 부정 입력 검사로 보장해야 한다.
- 최신 handoff의 2026-09-11 비교 UX 1단계는 가슴·허리의 명시적 검증 환산을 허용하고 저장 원본은 유지하도록 기록한다. 원본 저장 시 절반으로 바꾸라는 오래된 테스트 기대와 구분한다.
- 엔진은 RecommendationService, VNextComparisonEngineAdapter, RecommendationResultView에서 사용된다. 따라서 비교 관련 실패를 단순히 사용하지 않는 옛 코드라고 제외할 수 없다.

그 밖의 비교 방식·래글런·ZARA fixture·정적 소스 문자열 검사의 실패는 개별 기대와 현재 계약의 대조가 모두 끝난 것은 아니다. 미확정으로 유지하며 앱이 맞다는 전제로 기대값부터 바꾸지 않는다.

## 확인된 테스트 문제의 구체적 원인

- JourneyRemote.submitProductObservation이 항상 오류를 던진다. 현재 상품 전송 단계를 지원하지 않는 가짜 서버가 후속 경로를 차단한다. recoveryDoubleSubmitThenClearUsesTheNewestProductionState는 도달하지 않는 두 번째 이벤트를 계속 기다린다.
- 옷장 수정 성공 fixture는 요청한 그룹 C를 서버 읽기 응답에 포함하지 않는다. 현재 코드는 요청과 응답의 그룹 불일치를 성공으로 처리하지 않는다. 응답 fixture와 불일치 거부 검사를 각각 구성해야 한다.
- 기준 옷 교체 확인창을 요구하는 검사는 폐기된 영구 기준 옷 정책을 전제로 한다.
- 기존 화면 검사에는 이전 안내 제목·빈 옷장 문구·개인정보 문구가 남아 있다. 현재 버튼과 문구로 별도 실행한 4개 UI 검사는 통과했다. 이는 기존 10개 실패 전부의 대체 검증을 의미하지 않는다.

## 수정 계획

1. **등록 차단 해소 — 우선순위 높음.** 준비된 group_only_ingestion_axes_Apply.sql을 현행 서버와 대조하고 격리 DB에서 검증한다. 길이축을 모른다는 이유만으로 그룹 선택 전에 막지 않게 하되 유효하지 않은 값과 식별자 검증은 유지한다. 슬랙스 공식 경로 매핑은 별도 근거로 검토한다. 완료 기준: 해당 슬랙스와 미매핑 28개가 불러오기→그룹 선택→등록/비교로 진행하고, 잘못된 입력은 계속 거부된다. 실제 서버 적용은 별도 승인 및 적용 후 읽기 검증이 필요하다.
2. **실측 보존과 이미지 처리 개선.** 기존 파서에서 팔둘레 및 아직 비교에 쓰지 않는 원본 열을 버리지 않고 보존할 경로를 사용한다. 저장·표시 가능과 비교점수 사용을 구분하고 팔둘레를 임의로 점수에 추가하지 않는다. 기존 후보 우선순위·중복 영역 제거·취소와 시간 제한을 점검한다. 조기 종료는 전체 사이즈와 열의 완전성을 확인한 경우에만 검토한다. 완료 기준: 공식 3개 팔둘레 값 보존, 기존 값 불변, 두 느린 상품의 동일 환경 전후 측정과 아이폰 취소/재시도 확인.
3. **실패 검사 정비와 최종 재검증.** 가짜 서버를 현재 응답 계약에 맞추고 모든 대기에 제한 시간을 둔다. 폐기된 정책 검사는 현재 사용자 행동 검사로 교체한다. 미확정 비교·ZARA 실패는 먼저 원인을 판정하고 실제 결함만 수정한다. 완료 기준: 관련 실패가 근거와 함께 해소되고, 실제 로그인 후 등록→비교→저장→재실행 조회가 통과한다. 로그인 없이 실행한 검사를 실제 계정 성공으로 대체하지 않는다.
