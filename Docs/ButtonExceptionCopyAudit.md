# 버튼 예외 처리 문구 감사

점검일: 2026-09-16

범위: 사용자가 버튼을 누른 뒤 발생하는 입력 검증, 상품 로드, 비교, 내 옷 등록/수정/삭제, 기록 삭제, 로그인/계정 삭제, 이미지 분석 실패 문구. 일반 안내 문구와 마케팅 문구는 제외했다.

## 결론

- 정상적인 미매핑 상품은 오류 없이 비교 그룹 선택으로 이동하도록 수정·검증됐다.
- 입력 누락, 로그인 필요, 실측 부족, 삭제 실패 문구는 대체로 구체적이고 복구 행동이 명확하다.
- 아래 확인 항목은 2026-09-15 수정으로 반영했다. 서버 내부 상태·원문 오류는 사용자 문구에서 제거하고 진단 로그에만 유지한다.
- 2026-09-16에는 일시적 통신 실패와 서비스 점검이 필요한 계약·식별자·권한 실패를 분리했다. 전자는 네트워크 확인 후 재시도하고, 후자는 같은 요청을 반복하지 않고 문의하도록 안내한다.

## 발견 사항

| 우선순위 | 동작 | 현재 문제 | 권장 처리 |
|---|---|---|---|
| P1 | 상품 로드·비교 시작/승인/완료 | `FitMatchServerAuthorityError.errorDescription`이 `state/status/reason`, 런타임, API 같은 내부 표현을 포함하며 ViewModel이 이를 그대로 표시한다. | 내부 값은 로그에만 남기고 사용자에게는 `상품 정보를 확인하지 못했어요`, `비교를 시작하지 못했어요`, `같은 비교를 다시 시도해 주세요`처럼 단계별 문구를 반환한다. |
| P1 | 상품 observation/서버 응답 | `FitMatchSupabaseProductResolverError`가 `FitMatch DB`, `vNext`, `variant`, 서버 rejection detail을 사용자 문구로 반환할 수 있다. | 인증, 일시적 통신, 입력 거절, 응답 계약 오류로 분리하고 내부 detail은 표시하지 않는다. |
| P1 | 내 옷 등록 | `FitMatchClosetRegistrationRPCError.rejected`가 서버의 원문 message를 그대로 사용자 알림에 전달한다. SQL/RLS/constraint 문구가 노출될 수 있다. | 허용된 도메인 오류 코드만 사용자 문구로 변환하고 알 수 없는 message는 일반 저장 실패로 처리한다. |
| P1 | 비교 결과에서 다른 옷으로 비교·기록 저장 | `RecommendationResultView`의 세 catch가 `error.localizedDescription`을 `saveFailed`로 직접 반환한다. | 사용자 행동별 고정 문구를 사용하고 원문은 진단 로그에만 기록한다. |
| P2 | 상품 링크 입력 | 공통 검증은 빈 값과 지원하지 않는 URL만 구분한다. 잘못된 URL과 정상 URL이지만 미지원 쇼핑몰인 경우가 같은 상태가 된다. | `empty / malformed / unsupportedProvider / supported`로 분리한다. |
| P2 | 내 옷 링크 등록 | 위 공통 `.unsupported`를 다시 `올바른 상품 URL을 입력해 주세요`로 덮어써, 정상적인 미지원 쇼핑몰 URL도 형식 오류로 안내한다. Home/비교 시작 화면과 문구도 달라진다. | 모든 진입점에서 공통 `entryOutcome` 문구를 그대로 사용한다. |
| P2 | 상품 로드 실패 화면 버튼 | CTA가 `isNetworkFailure`만 `다시 시도`, 그 외에는 `다시 입력하기`다. 일시적 서버 오류나 응답 처리 오류도 URL 재입력을 요구한다. | URL 자체가 유효하면 `다시 시도`, malformed/unsupported일 때만 `다시 입력하기`를 사용한다. |
| P3 | 저장/삭제 알림 제목 | 동일 실패가 화면마다 `저장 실패`, `저장하지 못했습니다`, `보유한 옷 등록`으로 표시된다. | 제목을 `저장하지 못했어요`, `삭제하지 못했어요`, `비교를 시작하지 못했어요` 형태로 통일한다. |

## 정상 확인

| 동작 | 판정 |
|---|---|
| 빈 URL | `상품 링크를 입력해 주세요.`로 차단됨 |
| 미매핑 상품 | 오류가 아니라 A-G 비교 그룹 선택으로 이동함 |
| 실측 없음 | 실측/사이즈 부족 원인을 표시하고 비교를 차단함 |
| 로그인 없음 | 로그인 상태 확인 문구를 표시함 |
| 중복 내 옷 등록 | 이미 등록된 사이즈임을 명시함 |
| 서버 반영 여부가 불확실한 저장/삭제 | 무조건 재생성하지 않고 결과 확인 또는 동일 요청 재시도를 안내함 |
| 비교 대상 없음 | 내 옷 등록 또는 직접 선택 행동을 안내함 |
| 비교 불가 상품 | 미매핑과 구분하여 비교 불가를 표시함 |

## 표준 문구 기준

| 상태 | 제목/문구 |
|---|---|
| 빈 링크 | `상품 링크를 입력해 주세요.` |
| URL 형식 오류 | `올바른 상품 URL을 입력해 주세요.` |
| 미지원 쇼핑몰 | `현재는 무신사, 유니클로, ZARA 상품 링크를 지원합니다.` |
| 일시적 네트워크 실패 | `일시적인 연결 문제예요. 네트워크를 확인한 뒤 다시 시도해 주세요.` |
| 로그인 필요 | `로그인이 필요한 기능입니다. 다시 로그인한 뒤 시도해 주세요.` |
| 정상 미매핑 | 오류 문구 없음. `비교할 그룹을 선택해 주세요.` 표시 |
| 사이즈 없음 | `상품 정보는 불러왔지만 사이즈 정보를 찾지 못했어요.` |
| 비교 준비 부족 | 부족한 실측 또는 내 옷 정보를 구체적으로 표시 |
| 상품/응답 계약·식별자 오류 | `상품 정보를 서비스에서 확인하지 못했어요. 문제가 계속되면 문의해 주세요.` |
| 비교 서비스·권한·완료 계약 오류 | `비교 서비스에 문제가 있어요. 지금은 비교할 수 없어요. 문제가 계속되면 문의해 주세요.` |
| 저장 거절 | 허용된 도메인 사유를 표시하고, 미확인 원문은 `내 옷장에 저장하지 못했어요.`로 대체 |
| 반영 여부 불확실 | `서버 반영 여부를 확인하지 못했어요. 같은 요청을 다시 확인해 주세요.` |

## 권장 수정 순서

1. 사용자에게 직접 전달되는 서버 원문과 `localizedDescription`을 제거한다.
2. URL 검증 상태와 모든 URL 진입점 문구를 하나의 공통 매퍼로 통일한다.
3. 실패 단계별 CTA를 `다시 시도`와 `다시 입력`으로 정확히 분리한다.
4. 제목 어조를 통일하고 회귀 테스트로 문구 계약을 고정한다.

## 수정 결과

- 상품 링크 입력을 `empty / malformed / unsupported / supported`로 구분했다.
- 유효한 상품 URL의 처리 실패는 네트워크 오류 여부와 무관하게 `다시 시도`를 제공한다.
- 상품 로드, 비교 시작·완료, 내 옷 저장, 결과 저장에서 서버 원문 대신 단계별 고정 문구를 표시한다.
- 저장 관련 알림 제목을 `저장하지 못했어요`로 통일했다.

## 2026-09-16 원인별 안내 기준

- 재시도 대상: `URLError`와 HTTP 408, 425, 429, 5xx처럼 같은 요청을 다시 보내면 회복될 수 있는 전송 실패.
- 문의 대상: 필수 응답 누락·알 수 없는 상태·상품/variant/size 식별자 불일치·권한 거절·RPC/계약 오류·서버 분류/비교 서비스 불가.
- 사용자 수정 대상: 잘못된 URL, 미지원 쇼핑몰, 누락된 사이즈·실측·분류 선택. 이 경우 URL 재입력이나 입력 보완을 안내한다.
- 서버 원문, SQL/RLS 상태, 내부 `state/status/reason`은 사용자 문구에 노출하지 않고 진단 로그에만 남긴다.
