D. Root Cause
================================================================

1. A completed comparison Result can contain only a comparison-authorized
   product-size subset.

2. The current alternate-size Result was presentation state only; its exact
   server product_size_id did not reach Closet registration.

3. The Result flow opened the sheet without a fresh server authority/runtime
   check, allowing a sourced retailer product to take a local-only path.


================================================================
E. Result → Closet Preparation Design
================================================================

Added non-visual action:

FitMatchResultClosetRegistrationPreparationAction

Responsibilities:

- Preserve the existing manual/local-only Product path.
- For retailer-sourced Result Products, replay stored retailer facts through
  ShoppingProductViewModel.loadProductInfoFromHistoricalProduct(...).
- Consume fresh Supabase server authority/runtime.
- Build a Closet-registration Product using makeProductForClosetRegistration.
- Pass FitMatchClosetRegistrationServerContext to the existing Sheet.
- Map a preferred exact product_size_id to a fresh display ProductSize only
  through context.identity(for:).productSizeID.
- Block sourced Result registration when server authority, exact identity,
  structural policy, or product-wide measurement presence is unavailable.

No duplicate classification resolver or local global classification authority
was introduced.


================================================================
F. Full Runtime Size Restoration
================================================================

The Result's currentResult.product is not used as the Closet source.

Instead:

fresh historical retailer replay
  → current server authority/runtime
  → makeProductForClosetRegistration
  → full selected-runtime size collection retained on Product
  → serverRegistrationContext.registerableDisplaySizeIDs filters only picker UI

Example:

Full runtime:
  S  0 measurements
  M  chest 52
  L  chest 54 / shoulder 48 / length 70
  XL chest 57

Comparison authorized subset:
  L / XL

Closet picker:
  M / L / XL

S remains in Product/runtime but is not displayed in the Closet picker.


================================================================
G. Comparison Eligibility vs Closet Eligibility
================================================================

Closet eligibility:
  actual retailer garment measurement >= 1 for that exact display/runtime size

Comparison eligibility:
  DB readiness + eligible_candidate_sizes + begin_comparison authorization

These remain separate. A size with one garment measurement may be allowed in
Closet registration while still being comparison-ineligible.


================================================================
H. Current Displayed Size Exact Identity
================================================================

Recommended state:
  VNext completed batch.recommended.productSizeID

Temporary alternate analysis state:
  the completed batch's exact product_size_id is cached alongside the local
  presentation analysis key; display labels are never used as DB identity.

Historical Result with no retained batch identity:
  preferred selection = nil

No L/M/XL label-based product-size, variant, or runtime lookup is allowed.


================================================================
I. Recommended L → Register → L
================================================================

If the fresh runtime proves the completed batch's recommended L
product_size_id is registerable:

  Sheet initial selection = L
  final untouched save = L exact product_size_id


================================================================
J. Recommended L → Alternative XL → Register → XL
================================================================

If temporarySizeAnalysis is active and refers to completed-batch XL:

  Sheet preferred identity = XL exact product_size_id
  fresh runtime finds that exact XL display row
  Sheet initial selection = XL

No fallback to recommended L is allowed.


================================================================
K. XL Initial → User Selects M → DB Saves M
================================================================

The initial selection is only presentation intent.

At save time:

selected display ProductSize ID
  → serverRegistrationContext.identity(for:)
  → product_id / product_variant_id / product_size_id
  → upsert_closet_item

Therefore an XL initial selection changed by the user to M results in M's
exact product_size_id in the mutation payload.

================================================================
M. Server-First Call Ordering
================================================================

For a sourced Result with server registration context:

validation
  → stable client_item_id
  → exact product / variant / size identity
  → nested classification override when needed
  → upsert_closet_item
  → optional set_closet_reference
  → SwiftData persist

Remote upsert failure does not create a local SwiftData success fallback.
