C. Measurement Presence 정의

공통 enum FitMatchProductMeasurementPresence:

- available
  Parser가 actualMeasurements 상태에서 retailer garment measurement가 양수인 size를 하나 이상 확인했다. CONFIRMED runtime은 semantic conflict가 없고 양수 canonical measurement가 있으면 parser evidence가 불완전한 경우에만 추가 근거가 될 수 있다.

- none
  Parser가 actualMeasurements 상태의 비어 있지 않은 size table을 확인했고, 모든 size에 positive garment measurement가 없다.

- unknown
  Parser partial/unavailable/standard-size fallback 또는 size table 미확정 상태다. unknown은 none으로 바꾸지 않으며 기존 OCR/수동 recovery/error UX를 유지한다.

공통 helper FitMatchGarmentMeasurementPresence의 규칙:

- finite && value > 0인 garment measurement만 인정한다.
- measurementRecords가 있으면 records를 우선한다.
- legacy parser가 records 없이 scalar GarmentMeasurements만 채운 경우에만 scalar fallback을 허용한다.
- standardBodyChestCircumference는 garment measurement가 아니므로 제외한다.
- 이 helper는 comparison readiness, classification, canonicalization policy를 만들지 않는다.

D. Size measurement eligibility

- ShoppingProductViewModel은 parser apply 시점에 product-wide presence와 raw positive measurement source-size identity set을 먼저 보존한다.
- vNext runtime에서는 runtime source_size_key를, legacy runtime adapter에서는 explicit externalSizeID를 parser observation source-size identity와 연결한다.
- display label로 product_size_id를 다시 찾지 않는다.
- exact runtime display size ID마다 closetRegisterableDisplaySizeIDs에 eligibility를 저장한다.
- LinkClosetRegistrationPreparation의 transient FitMatchClosetRegistrationServerContext가 classificationState, exact product/variant/size UUID map, registerableDisplaySizeIDs를 함께 보유한다.
- Product.sizes 및 server runtime source data에는 S/M/L/XL 전체를 보존한다.
- AddComparedProductToClosetSheet의 server-first linked registration picker만 registerableDisplaySizeIDs에 포함된 size로 필터한다.
- 재고 상태 AVAILABLE/SOLD_OUT/UNKNOWN은 measurement eligibility에 영향을 주지 않는다.

F. Closet 최종 flow

상품 링크
→ Parser가 상품 facts와 raw size measurement를 수집
→ Supabase product observation/resolve/runtime
→ productMeasurementPresence 검사
→ none이면 상품 preview는 표시하고 registration Sheet 진입, remote upsert, SwiftData write를 모두 차단
→ available이면 exact runtime identity와 registerable display size만 registration context에 전달
→ AddComparedProductToClosetSheet picker는 실측 있는 size만 표시
→ validation
→ stable client_item_id 유지
→ exact product_id/product_variant_id/product_size_id + 필요 시 nested closet_classification_override
→ remote upsert
→ optional set_closet_reference
→ remote 성공 이후 SwiftData 저장

선택 size는 UI와 prepareServerFirstSubmission 양쪽에서 measurement eligibility를 검사한다. DB는 여전히 canonical measurement final safety gate다.

G. Compare 최종 flow

상품 링크
→ Parser facts
→ Supabase observation/runtime
→ productMeasurementPresence 검사
→ none이면 "이 상품은 실측 정보가 없어 비교할 수 없습니다."로 error step 전환 및 return
→ available/unknown이면 기존 classification recovery, serverComparisonReadiness, reference selection plan, begin comparison, Swift scoring, complete comparison 흐름을 그대로 사용

available은 comparison-ready가 아니다. 예를 들어 chest 한 개만 있으면 product gate는 통과하지만 DB readiness가 INSUFFICIENT_MEASUREMENTS 또는 MEASUREMENTS_REQUIRED이면 비교는 기존처럼 차단된다.

I. Exact UUID 검증

- product_id: server runtime product.id에서 받는다.
- variant_id: 선택된 runtime variant.id에서 받는다.
- product_size_id: runtime size.id(vNext) 또는 explicit legacy productSizeID에서 받는다.
- 보관: ShoppingProductViewModel.closetRegistrationIdentitiesByDisplaySizeID
- 전달: FitMatchClosetRegistrationServerContext.identity(for: selectedDisplaySizeID)
  → FitMatchComparedProductClosetRegistration.SaveRequest.serverIdentity
  → FitMatchUpsertClosetItemRequest
- REVIEW_REQUIRED raw measurement mapping은 parser observation identity와 runtime source_size_key를 사용한다. display label이 다른 "L (Runtime)" fixture도 source_size_key "L"을 통해 exact UUID에 연결되는 테스트를 추가했다.
- 정상 server-first link path에서는 sizeName/colorName으로 DB UUID를 재탐색하지 않는다.
- FitMatchClosetSyncCoordinator의 uniqueRuntimeSizeIdentity는 remote client_item_id row가 없는 legacy local-only recovery bounded path로만 남아 있으며 이번 작업에서 변경하지 않았다.
