# 앱 하드코딩 ↔ DB 분류 규칙 동등화 결과

## 목표 범위

- 현재 앱의 브랜드 카테고리·상품명 기반 분류 동작을 변경하지 않는다.
- 향후 하드코딩을 제거하고 DB 조회 방식으로 전환할 수 있도록 동일 규칙과 우선순위를 DB에 보관한다.
- 대분류, 세부분류 및 동일 분류 내 옷 선택 가능 여부를 640개 고유 상품으로 회귀 검증한다.

## 반영 구조

| 테이블 | 역할 |
|---|---|
| `fitmatch_taxonomy.runtime_rule_sets` | 앱 소스 체크섬, 실행 순서, 규칙 버전 |
| `fitmatch_taxonomy.runtime_classification_rules` | 판매처·단계·입력 범위·키워드·우선순위·출력 매핑 |
| `fitmatch_staging.runtime_classification_regression_cases` | 640개 상품의 현재 앱 기준 기대 결과 |
| `fitmatch_staging.runtime_classification_parity_runs` | 일치·불일치·미매칭 수와 결과 체크섬 |

## 전환 조건

현재 앱은 계속 하드코딩 규칙을 실행한다. 향후 DB 조회 방식으로 전환할 때에는 DB 규칙 평가기를 별도 구현한 후 동일 640건에서 현재 앱 결과와 DB 평가 결과가 모두 일치해야 한다. 규칙 소스 체크섬이 달라지거나 회귀 결과가 한 건이라도 달라지면 하드코딩 제거를 차단한다.

## 보안 상태

새 테이블은 RLS를 활성화하고 `anon`, `authenticated` 권한을 제거했다. 현재 앱에는 노출되지 않는다. 실제 런타임 조회 전환 시 읽기 전용 API 스키마와 정책을 별도로 추가해야 한다.
# 2026-08-06 DB 독립 평가 정정

`fitmatch_taxonomy.evaluate_runtime_classification`을 추가하고 입력 범위를
`source_path`, `specific_source`, `product_name`, `combined`로 분리하여 DB 규칙 자체를 실행했다.
