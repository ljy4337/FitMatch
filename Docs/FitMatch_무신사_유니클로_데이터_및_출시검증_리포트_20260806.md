## 1. 데이터 수집 및 데이터화 방식

FitMatch는 쇼핑몰 데이터를 그대로 덮어쓰지 않고 다음 두 계층으로 보관한다.

1. 원본 계층: 쇼핑몰 사이즈명, 항목명, 항목 코드, 값, 단위, 설명, 출처와 파싱 형식을 보존한다.
2. 비교 계층: 검증된 항목만 canonical measurement code와 cm 값으로 변환한다.

핵심 원칙은 다음과 같다.

- 가슴둘레와 가슴단면은 같은 값으로 취급하지 않는다. 의류 둘레만 필요 시 2로 나눠 단면으로 비교한다.
- 일반 소매길이와 화장(등 중심부터 소매 끝)은 직접 비교하지 않는다.
- 앞기장과 뒤기장을 합치지 않는다.
- 플랫폼이 제공하지 않은 값은 추정하여 저장하지 않는다.
- 의미가 불명확한 원본은 보존하되 추천 점수에서 제외한다.

지원 범위와 항목별 변환 기준은 `무신사_유니클로_카테고리별_사이즈저장_비교표.md`에 정리되어 있다.

## 3. 목표별 상세 평가

### 목표 1 — 원본 정보 동일성

코드·fixture 기준으로는 원본 데이터의 항목명, 값, 단위와 출처를 보존하고 정규화 값을 별도로 생성하므로 추적 가능성이 높다. 무신사 실제 상품 4개와 유니클로 실제 상품을 이용한 등록 결과도 확인됐다.

실제 판매 상품 300개의 공식 공개 응답 조사 자료는 확보되어 있다. 그러나 이 데이터와 FitMatch 앱 파서가 생성한 저장 레코드를 상품별로 일괄 대조하지 않았으므로, 현재 증거로는 **공식 원본 표본 확보, 앱 수집 결과와의 300건 대조는 미완료**로 판정한다.

### 목표 2 — 동일 카테고리 비교 정확성

자동 비교는 단순히 `상의`처럼 넓은 분류만 같다고 실행하지 않는다. 성별, 세부 카테고리, 소매·바지 길이군, canonical profile 및 정확한 측정 코드가 호환돼야 한다. 반팔/긴팔, 반바지/긴바지, 일반 소매/화장처럼 의미가 다른 조합을 제외하는 테스트가 통과했다.

따라서 현재 코드가 지원하는 분류와 측정 항목 안에서는 **정확하게 동작**한다고 판정한다. 미분류·신규 쇼핑몰 카테고리는 controlled fallback 또는 사용자 확인 대상으로 남겨야 한다.

### 목표 3 — 결과 신뢰도

신뢰도는 아래 네 지표를 함께 봐야 한다.

| 지표 | 현재 결과 |
|---|---|
| 원본 추적성 | 높음 — 원본과 변환값 분리 저장 |
| 비교 정책 정확성 | 높음 — 결정적 관련 테스트 통과 |
| 측정 커버리지 | 상품별 가변 — 제공되지 않거나 호환되지 않는 값은 제외 |
| 실제 사용자 완료율 | 낮음 — 최신 공유 비교 0/2 완료 |

따라서 계산 결과가 만들어진 경우의 내부 일관성은 높지만, 앱 전체 서비스 관점의 “높은 신뢰도”는 아직 주장할 수 없다. 최소 출시 기준은 대표 상품군별 충분한 표본에서 원본 필드 일치율, 분류 정확도, 비교 완료율과 사용자 정답 평가를 별도로 계측하는 것이다.

## 4. 출시 후 예상 문제점

### 출시 차단

1. 공유 확장 성공 뒤 FitMatch 비교 화면이 열리지 않는 문제(FM-LIVE-001).
2. `보러가기`가 앱을 전면으로 열지 못하는 문제(FM-LIVE-002).
3. 실제 비교 시작 전에 성공 문구를 표시하고 URL 복구 수단이 없는 문제(FM-LIVE-003).

### 높은 우선순위

1. 무신사·유니클로 API/HTML 변경 시 수집 실패 또는 일부 필드 누락 가능.
2. 인기 카테고리별 표본 수와 정답 라벨이 없어 외적 정확도 수치가 과대평가될 위험.
3. actual-size가 null인 무신사 상품은 OCR/HTML fallback 품질에 의존.
4. 신규·모호 카테고리가 `.other` 또는 사용자 확인으로 몰릴 가능성.
5. 성능 UI 테스트의 signal kill 원인을 실기기에서 확인하지 않으면 출시 후 느린 시작 또는 불안정성을 놓칠 수 있음.

### 운영 권고

- 파서 버전, 성공률, 필드 누락률, fallback 사용률을 쇼핑몰·카테고리별로 기록한다.
- 비교 결과에 적용 측정 수, 제외 측정과 이유, 데이터 출처·수집 시점을 표시한다.
- 공유 URL은 비교 화면 표시가 확인되기 전까지 삭제하지 않고 홈에서 이어하기를 제공한다.
- 실제 판매량 또는 이용량을 근거로 카테고리별 층화 표본을 만들고 주기적으로 회귀 검증한다.

## 5. 출시 후 예상 긍정 요인

1. 원본과 정규화 데이터를 분리해 잘못된 변환을 감사하고 재처리하기 쉽다.
2. 동일 사이즈명 대신 실제 의류 실측과 Reference Garment를 비교해 사용자에게 직접적인 가치를 제공한다.
3. 호환되지 않는 측정을 억지로 점수에 포함하지 않아 잘못된 고신뢰 추천을 줄인다.
4. 비교 커버리지와 제외 이유를 설명할 수 있어 결과의 투명성을 높일 기반이 있다.
5. 242개의 결정적 테스트가 파서, 분류, 비교, 영속성의 핵심 회귀를 방어한다.
6. 무신사와 유니클로 모두 링크 기반 옷장 등록이 실제 사용자 여정에서 성공했다.
