# 무신사·유니클로 카테고리별 사이즈 저장 및 비교표

작성 기준: 2026-07-28  
코드 기준: `musinsa_actual_size_mapping_v8`, `musinsa_fallback_mapping_v1`, `uniqlo_kr_size_chart_mapping_v6`

## 문서 읽는 방법

- **내 옷장 표시**는 플랫폼 사이즈표에서 받은 원본 항목명과 원본 값을 뜻한다.
- **FitMatch 비교값**은 플랫폼 간 비교를 위해 cm와 측정 기준을 통일한 값이다.
- 플랫폼 사이즈표에 없는 항목은 저장하거나 추정하지 않는다.
- 원본 항목이 존재하지만 의미를 확인하지 못한 경우 원본 기록은 보존하되 매칭률 계산에서는 제외한다.
- 아래 표의 항목은 해당 카테고리에서 지원하는 항목이다. 실제 상품마다 제공되는 열은 다를 수 있다.

## 1. 내 옷장에 공통으로 저장되는 정보

각 사이즈 옵션마다 다음 정보를 저장한다.

| 저장 정보 | 설명 |
|---|---|
| 사이즈명 | `S`, `M`, `L`, `30`, `76` 등 플랫폼 원본 사이즈명 |
| 원본 항목명 | `가슴단면`, `허리 둘레 (상품 사이즈)`, `밑위 길이` 등 |
| 원본 항목 코드 | 유니클로 API 코드 또는 플랫폼이 제공한 코드 |
| 원본 값 | 플랫폼이 제공한 문자열과 단위 |
| 원본 설명 | 측정 설명과 변환 근거 |
| 수집 형식 | 무신사 타입 번호, 무신사 이미지/HTML 표, 유니클로 항목 구성 |
| FitMatch 측정 코드 | 플랫폼 간 비교에 사용하는 측정 기준 |
| FitMatch 비교값 | 단위 및 둘레/단면 변환을 마친 cm 값 |

내 옷장 화면에는 원본 항목명과 원본 값을 우선 표시한다. 예를 들어 유니클로가 `허리 둘레 (상품 사이즈) 80cm`를 제공하면 내 옷장에는 이 원본 표현을 표시하고, 비교용으로는 허리단면 `40cm`를 별도 보관한다.

### 2.6 원피스

무신사 원피스 표가 상의형 구조라면 어깨·가슴·총장·소매를 저장하고, 표에 허리·엉덩이가 있으면 함께 저장한다. 비교 시에는 원피스 정책에 따라 가슴·허리·엉덩이 중 최소 한 항목과 공통 실측을 사용한다.

### 2.7 신발

이미지/HTML 사이즈표에서 `발길이`, `한국`, `Korea`, `foot length`를 인식하면 원본을 저장하고 뒤꿈치부터 발끝까지의 cm 값으로 비교한다.

### 2.8 무신사 입점 쇼핑몰 이미지·HTML 표

`methodSource = musinsa_fallback`, `methodProfile = structured_size_table`로 저장한다.

- 단면 값: 그대로 사용
- 둘레 값: 원본은 유지하고 비교값은 `× 0.5`
- mm: 비교값을 cm로 `× 0.1`
- inch: 비교값을 cm로 `× 2.54`
- 변환 내역: 원본 설명 필드에 함께 저장

## 3. 유니클로 카테고리별 저장 형식

### 3.1 상의

| 유니클로 원본 코드 | 일반 표시명 | 내 옷장 원본 저장 | FitMatch 비교 기준 |
|---|---|---:|---|
| `shoulder-width` | 어깨너비 | 원본 그대로 | 어깨 봉제선 간 너비 |
| `body-width` | 가슴너비 | 원본 그대로 | 겨드랑이 가슴단면 |
| `body-length-back` | 등쪽 몸길이 | 원본 그대로 | 뒤목점부터 밑단 |
| `body-length` | 몸길이 | 원본 그대로 | 뒤목점부터 밑단으로 확인된 상품 |
| `knit-body-length-front` | 니트 앞길이 | 원본 그대로 | 현재 공통 총장 코드로 저장 |
| `sleeve-length` | 소매길이 | 원본 그대로 | 어깨선부터 소매 끝 |
| `sleeve-length-cb` | 등 중심부터 소매까지 | 원본 그대로 | 등 중심부터 소매 끝 |

### 3.2 아우터

유니클로 아우터는 상의와 같은 원본 코드를 사용한다.

| 유니클로 항목 | FitMatch 비교 기준 | 무신사 대응 |
|---|---|---|
| 어깨너비 | 어깨 봉제선 간 너비 | 어깨너비 |
| 몸 너비 | 가슴단면 | 가슴단면 |
| 몸길이/등쪽 몸길이 | 뒤목점 총장 | 총장 |
| 소매길이 | 어깨선 소매 | 소매길이 |
| 등 중심 소매 | 등 중심 소매 | 화장 |

아우터끼리 비교할 때 가슴은 필수 핵심 항목이며, 최소 2개 공통 항목이 필요하다.

### 3.3 하의

| 유니클로 원본 코드 | 일반 표시명 | 내 옷장 원본 저장 | FitMatch 비교값 |
|---|---|---:|---:|
| `waist-product-size` | 허리 둘레(상품 사이즈) | 둘레 원본 그대로 | 원본 둘레 ÷ 2 |
| `hip-product-size` | 엉덩이 둘레(상품 사이즈) | 둘레 원본 그대로 | 원본 둘레 ÷ 2 |
| `thigh` | 허벅지 너비 | 원본 그대로 | 그대로 |
| `rising-length` | 밑위 길이 | 원본 그대로 | 앞밑위 그대로 |
| `bottom-width` | 밑단 너비 | 원본 그대로 | 그대로 |
| `inseam` | 인심/다리 길이 | 원본 그대로 | 인심 그대로 |

유니클로 하의에는 아웃심 총장이 없고 인심만 있는 상품이 많다. 이 경우 무신사 `총장`과 비교하지 않고 무신사 `인심`이 있을 때만 길이를 비교한다.

### 3.4 스커트

| 유니클로 원본 코드 | 내 옷장 원본 저장 | FitMatch 비교값 |
|---|---:|---:|
| `skirt-length` | 스커트 길이 원본 | 허리선부터 밑단 |
| `waist-product-size` | 허리둘레 원본 | 둘레 ÷ 2 |
| `hip-product-size` | 엉덩이둘레 원본 | 둘레 ÷ 2 |

### 3.5 원피스

실제 유니클로 표에서 제공되는 `body-width`, `body-length*`, `shoulder-width`, `sleeve-length*`, 허리/엉덩이 항목을 모두 원본으로 저장한다. 비교는 원피스의 공통 측정 코드만 사용한다.

### 3.6 속옷·이너웨어

유니클로 표에 현재 지원하는 허리·엉덩이·가슴·몸길이 코드가 있으면 원본을 저장한다. 밑가슴처럼 별도 코드 매핑이 확인되지 않은 항목은 원본은 보존하지만 자동 비교에서 제외한다.

- 후보: 어깨, 가슴, 총장, 허리, 엉덩이
- 최소 2개 공통 항목
- 가슴·허리·엉덩이 중 최소 1개 필요

### 신발

- 발길이 1개를 동일한 뒤꿈치–발끝 기준으로 비교한다.

각 항목 점수는 `100 - 절대 차이(cm) × 5`이며 0–100 범위로 제한한다. 최종 매칭률은 실제 비교된 항목의 가중 평균이다.

## 6. 동일 플랫폼 비교와 플랫폼 간 비교의 차이

| 비교 상황 | 우선 규칙 |
|---|---|
| 무신사 API 타입이 양쪽 모두 동일 | 같은 원본 코드/원본 항목을 직접 비교 |
| 유니클로 항목 구성이 양쪽 모두 동일 | 같은 유니클로 원본 코드를 직접 비교 |
| 무신사 API와 무신사 이미지/HTML 표 | FitMatch 측정 코드로 변환 후 비교 |
| 서로 다른 무신사 타입 | FitMatch 측정 코드로 변환 후 비교 |
| 무신사와 유니클로 | 위 직접 비교표의 FitMatch 측정 코드로 비교 |

측정 시작점이나 의미가 다른 항목은 이름이 비슷해도 비교하지 않는다. 비교 가능한 항목이 최소 조건보다 적으면 매칭률을 만들지 않고 `정보 부족`으로 처리한다.
