## PHASE A — authority / provenance correctness

### A1 — preserve and publish strict HJ-P0-001 proof

- **Files / symbols:** `RecommendationService.makeCompletedVNextHistory`,
  `completedVNextHistoryIsServerBacked` / current equivalent;
  `ShoppingProductViewModel.completeVNextRecommendation`; current-session alternate
  size helper in `RecommendationResultView`.
- **Problem:** published `.serverConfirmed`-only local History guard discards a
  completed, server-authorized current USER_EXPLICIT comparison.
- **Strategy:** accept only exact matching current server permit/begin/complete V4
  proof.  Validate comparison/run ID, target/variant/reference, eligible/recommended
  size, authorization and candidate fingerprints, effective authority, personal
  projection revision/hash/input/evidence/resolver fingerprints.  Complete first.
- **Must not change:** no generic `.userExplicit` admission; no fresh scorer;
  no server contract relaxation.
- **Tests:** J07/J09/J11/J13 completion, global confirmed unchanged, stale/cleared/local
  UE / mismatched identity / candidate rejection, current session alternate-size view.

### A2 — map Result other-item target from server effective authority without mutation

- **Files / symbols:** `RecommendationResultView.compare(with:)`,
  `applyServerAuthority`, `ResultReferenceComparisonPersistence`; optionally a shared
  internal product mapper used by Shopping and Result.
- **Problem:** target becomes globally confirmed and may use policy code as garment;
  successful server completion can have no local result/history.
- **Strategy:** build a comparison-local immutable target from current runtime effective
  classification.  Keep global/personal provenance exact and never mutate the existing
  Result Product.  Pass it through A1 proof after successful completion.
- **Tests:** UE other-item automatic/direct and explicit-manual; old Result unchanged;
  global target unchanged; no local-only/stale UE history.

### A3 — hydrate V4 history from its immutable effective snapshot

- **Files / symbols:** `VNextHistoryCacheHydrator`, `RecommendationHistory` model
  snapshot construction/current adapter.
- **Problem:** V4 recovered history uses live global fields and global provenance.
- **Strategy:** decode `effective_classification_at_begin` and relevant personal
  projection from V4 authority snapshot; construct a per-history immutable display
  snapshot.  Legacy V3 remains clearly legacy/fail-safe.
- **Tests:** fresh hydration of two different UE revisions of same target; global V4/V3
  unchanged; missing/inconsistent snapshot does not invent global authority.

### A4 — separate shopping Recovery authority from Closet override authority

- **Files / symbols:** `AddComparedProductToClosetSheet`,
  `LinkClosetRegistrationView`, classification provenance policy,
  `FitMatchClosetSyncCoordinator`, misleading effective-confirmed helper.
- **Problem:** personal shopping target selection is implicitly reclassified and synced
  as a personal Closet manual override.
- **Strategy:** require a separate explicit Closet classification intent before a Closet
  override; otherwise retain sourced data non-authoritatively or stop with an intentional
  user explanation.  Do not use parser inference to transfer authority.  Full/partial
  link handling must not mark personal authority global or treat policy code as garment.
- **Tests:** UE → full/partial Add to Closet produces no manual override; global confirmed
  linked add unchanged; direct manual Closet edit still creates only its intended override.
